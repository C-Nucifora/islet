# Islet UI Audit — 10 August 2026

## Scope and evidence

This audit covers the complete SwiftUI/AppKit interface in `Islet/UI`, `Islet/Activities`,
`Islet/Settings`, and the menu-bar scene in `Islet/App`. It combines source inspection with the
real hosted Bluetooth-sneak and power-screen snapshots and the existing 345-test macOS suite.

The audit did not include a manual VoiceOver traversal, Accessibility Inspector capture, Instruments
trace, localization build, or testing on every notched Mac size. Findings that need one of those
tools are explicitly framed as validation work, not asserted as measured failures.

## Changes applied before the audit

1. **Bounded event marquee** (`875515b`) — system events now use an exact 120-point trailing
   viewport rather than expanding as far as 175 points. Overflowing title/subtitle content pauses,
   scrolls at a constant reading speed, pauses at the end, and repeats. A soft edge mask communicates
   hidden content. Reduce Motion receives a static clipped line, while VoiceOver retains the complete
   announcement. Pure timing and hosted-width regressions were added.
2. **Product-specific menu-bar icon** (`cf3023b`) — the generic `capsule.fill` was replaced with a
   scalable monochrome Islet silhouette: flared shoulders, centered notch cutout, and rounded island
   body. It uses native menu-bar coloring, carries an explicit accessibility label, and has a path
   geometry regression test.

The compact event change reduces the maximum event-text contribution to the right flank by 55
points (31%). It does not alter notch alignment or panel geometry.

## Platform conformance verdict

**Pass.** Islet does not read as a ported website. Its menu-bar extra, settings form, list reordering,
system pickers, AppKit panel, SF Symbols, drag/drop, sharing service, and accessibility announcements
are all recognizably macOS-native. The custom island navigation earns its departure from standard
window navigation because the hardware notch is the product surface, not decorative chrome.

The main platform risk is not visual authenticity; it is that dense pointer-first controls do not
yet expose an equally complete keyboard and VoiceOver experience.

## Executive summary

- **Health:** 14/20 (Good)
- **Issues:** 0 P0, 4 P1, 5 P2, 2 P3
- **Strongest areas:** product identity, notch/panel geometry, native APIs, data-density hierarchy,
  sampling efficiency, and existing pure/hosting regression coverage.
- **Highest priorities:** action semantics, shelf item removal without hover, complete Reduce Motion
  handling, and layout stress resistance.
- **Recommended sequence:** `/impeccable harden` → `/impeccable adapt` → `/impeccable optimize` →
  `/impeccable document` → `/impeccable polish`.

## Detailed findings

### P1 — Major

#### [P1] Icon-only actions do not consistently expose their action or state

- **Location:** `Activities/NowPlaying/NowPlayingViews.swift:173`,
  `Activities/Timer/TimerActivity.swift:192`, `Activities/Shelf/ShelfActivity.swift:54`,
  `Activities/Clipboard/ClipboardActivity.swift:159`, `UI/IdleDashboardView.swift:69`, and
  `Activities/Calendar/CalendarActivity.swift:146`.
- **Category:** Accessibility / Platform conformance
- **Impact:** A sighted user can infer shuffle, repeat, complete, join, delete, share, add time, and
  cancel from symbols. A VoiceOver user may hear a symbol-derived name or a generic button without
  the action, target, or current state. Shuffle and repeat also communicate state mainly by color.
- **Guideline:** Every interactive image needs a concise action label; stateful controls need a
  value or selected state. Meaning cannot depend only on color.
- **Recommendation:** Introduce a small `IslandIconButton` wrapper with required label and optional
  help/value. Apply explicit labels such as “Pause”, “Add one minute”, “Join meeting”, “Complete
  reminder: …”, “Share shelf by AirDrop”, and “Clear clipboard”. Expose shuffle/repeat state with
  `accessibilityValue` or selected traits.
- **Suggested command:** `/impeccable harden`

#### [P1] Per-file shelf removal only exists while the pointer is hovering

- **Location:** `Activities/Shelf/ShelfActivity.swift:135-150`
- **Category:** Accessibility / Platform conformance
- **Impact:** Keyboard and VoiceOver users cannot reliably discover or focus the per-item delete
  control because the button is absent until pointer hover. Their practical fallback is clearing the
  whole shelf, which is materially more destructive.
- **Guideline:** Essential actions must not depend on hover. Pointer hover may enhance an action but
  cannot be its sole discovery or availability mechanism.
- **Recommendation:** Keep the overlay visible while the item or remove button has accessibility or
  keyboard focus, and add a native context menu with “Remove from Shelf”. Preserve hover as the
  quiet visual presentation for pointer users.
- **Suggested command:** `/impeccable harden`

#### [P1] Reduce Motion is centralized but not applied to every decorative animation

- **Location:** `Core/Motion.swift:13-32` is the good shared gate;
  `Activities/NowPlaying/NowPlayingViews.swift:19-40` and `Activities/HUD/HUDView.swift:37-59`
  bypass it. Timer rings at `Activities/Timer/TimerActivity.swift:132` and `:166` also use animation
  timelines, although their changing progress conveys useful state rather than pure decoration.
- **Category:** Accessibility
- **Impact:** Users who request reduced motion still see continuously oscillating playback bars and
  animated HUD interpolation. The marquee correctly honors the preference, making the remaining
  exceptions more inconsistent.
- **Guideline:** Reduced Motion should replace decorative continuous movement with a stable state;
  useful progress may continue updating without interpolation.
- **Recommendation:** Pause the music bars under Reduce Motion, gate HUD interpolation through
  `Motion.gated`, and update timer progress discretely without animated interpolation when the
  preference is active.
- **Suggested command:** `/impeccable animate`

#### [P1] Fixed geometry has no explicit text/localization stress strategy

- **Location:** `Core/Metrics.swift:5-7` fixes the island at 480 points;
  `Activities/Battery/BatteryExpandedView.swift:103-137` fixes three metric columns;
  `UI/ExpandedContainerView.swift:72-83` derives the switcher from the remaining ear width;
  `Settings/SettingsView.swift:208` fixes the settings content to 440×520.
- **Category:** Adaptivity
- **Impact:** Long device names are now contained, but localized labels, long media metadata,
  increased contrast/bold text, and future metrics can still compress or truncate dense surfaces.
  The power view already relies on 9-point labels and exact column arithmetic to fit.
- **Guideline:** Native layouts should preserve action availability and reading order under realistic
  text expansion, even when the product deliberately has a fixed outer shell.
- **Recommendation:** Keep the outer island width stable, but make its internal rows adaptive with
  `ViewThatFits`, layout priorities, compact/expanded label variants, and tested overflow behavior.
  Add fixtures with 2× text length and representative German/French strings before changing widths.
- **Suggested command:** `/impeccable adapt`

### P2 — Minor

#### [P2] Permission-denied and loading states are informational dead ends

- **Location:** `UI/IdleDashboardView.swift:47-51`, `:87-91`, and `:140-142`;
  `Activities/Calendar/CalendarActivity.swift:50-83`.
- **Category:** Accessibility / Implementation integrity
- **Impact:** “Calendar access off” and “Reminders access off” explain the state but offer no recovery
  action. Before the first permission result, empty data can also read as “No events today” or “All
  clear,” conflating loading, denial, failure, and genuine emptiness.
- **Recommendation:** Model `loading`, `ready`, `denied`, and `failed` explicitly. Give denied states
  an “Open Privacy Settings” action and failures a retry where recovery is possible.
- **Suggested command:** `/impeccable onboard`

#### [P2] Image decoding and application lookup occur in render paths

- **Location:** `Activities/NowPlaying/NowPlayingViews.swift:8`, `:68`, `:122`, `:139`, and
  `:212-229`; `Activities/Shelf/ShelfActivity.swift:128`.
- **Category:** Performance
- **Impact:** `NSImage(data:)`, Launch Services lookup, and application icon loading can repeat as
  observable objects publish and timelines redraw. Artwork and source strips are precisely the
  surfaces that update most often, so occasional main-thread stalls would be visible.
- **Recommendation:** Decode artwork/thumbnails when data changes, cache by stable artwork/source
  identity, and add a small application metadata cache for name/icon lookup. Confirm with Instruments
  before and after; do not add caching without measuring invalidation and memory behavior.
- **Suggested command:** `/impeccable optimize`

#### [P2] Calendar queries and parsing are main-actor synchronous work

- **Location:** `Activities/Calendar/CalendarActivity.swift:61-83` and `:86-95`.
- **Category:** Performance
- **Impact:** `events(matching:)`, sorting, and link detection run from a `@MainActor` activity every
  30 seconds. Small agendas are likely harmless, but calendars with many overlapping events or long
  notes can briefly contend with island animation and input.
- **Recommendation:** Profile a worst-case calendar first. If measurable, snapshot only the
  EventKit-owned values required on the main actor, then map/sort/link-detect immutable values off
  actor and publish one result on the main actor.
- **Suggested command:** `/impeccable optimize`

#### [P2] Visual semantics are coherent but encoded as scattered literals

- **Location:** Repeated `.white.opacity(0.06...0.25)` surfaces and direct `.orange`, `.green`,
  `.blue`, `.cyan`, and `.purple` accents across `UI` and `Activities`; typography includes repeated
  `.system(size: 9)` literals in battery, reminders, ports, and shelf views.
- **Category:** Appearance & theming / Implementation integrity
- **Impact:** The UI currently looks related, but changes to contrast, hierarchy, or high-contrast
  behavior require many hand edits. Similar surfaces already use slightly different background
  opacity and type rules.
- **Recommendation:** Document semantic roles before extracting tokens: island primary/secondary,
  subtle plate, selected plate, divider, positive, caution, danger, and per-activity accent. Preserve
  the black island and native Settings appearance rather than forcing one theme across both.
- **Suggested command:** `/impeccable document`

#### [P2] Clipboard privacy disclosure arrives after activation and has no status affordance

- **Location:** `Settings/SettingsView.swift:188-193` and
  `Activities/Clipboard/ClipboardActivity.swift:34-88`.
- **Category:** Accessibility / Implementation integrity
- **Impact:** The setting warns that passwords may be captured, but the warning is secondary text
  shown only after the toggle is on. Once enabled, there is no persistent compact indicator that
  distinguishes “clipboard monitoring active but empty” from “disabled.”
- **Recommendation:** Put the privacy consequence in the toggle’s help/description before the state
  changes, consider a one-time confirmation, and provide a clear “session only; clears on quit”
  status. Keep the feature off by default.
- **Suggested command:** `/impeccable clarify`

### P3 — Polish

#### [P3] Settings is fixed-size and cannot be resized

- **Location:** `Settings/SettingsView.swift:208` and `Support/SettingsOpener.swift:17-21`.
- **Category:** Adaptivity / Platform conformance
- **Impact:** The grouped form scrolls, so tasks remain possible, but the user cannot enlarge a dense
  settings window or compare more sections at once.
- **Recommendation:** Give the window a sensible minimum/ideal size and include `.resizable` in its
  style mask. Preserve the compact initial footprint.
- **Suggested command:** `/impeccable adapt`

#### [P3] Tiny supporting text is used as a recurring density escape hatch

- **Location:** `.system(size: 9)` in battery, reminder, ports, and shelf views, including
  `Activities/Battery/BatteryExpandedView.swift:87` and `:170`.
- **Category:** Accessibility / Appearance
- **Impact:** The snapshot remains legible at 2× rendering, but real-world viewing distance,
  low-vision settings, and non-Retina fallback displays can make 9-point secondary information hard
  to scan.
- **Recommendation:** Establish one compact supporting style and test whether 10–11 points can fit
  after adaptive row work. Keep 9 points only where a measured constraint proves it necessary.
- **Suggested command:** `/impeccable typeset`

## Patterns and systemic issues

1. **Pointer-first icon controls:** plain symbol buttons are visually elegant but action names,
   state, focus visibility, and help are applied inconsistently.
2. **Fixed-shell pressure leaks inward:** the 480-point shell is a valid product constraint, but
   internal layouts often answer it with exact widths and 9-point type rather than adaptive
   composition.
3. **State models favor success/empty:** calendar and reminders distinguish denial, but not loading
   and recoverable failure throughout the UI.
4. **Good performance discipline is uneven at presentation boundaries:** monitors and histories are
   gated well, while image/application metadata work is still performed from view builders.
5. **A visual system exists implicitly:** black surface, white hierarchy, low-opacity plates,
   semantic status colors, SF Symbols, compact radii. It needs documentation and tokens, not a new
   visual identity.

## Positive findings

- The island has a clear, product-specific visual and interaction model.
- Notch geometry is unusually well isolated and regression-tested, including asymmetric hardware,
  real panel frames, multiple displays, stale measurements, and height tiers.
- SwiftUI/AppKit boundaries are intentional: native menus, Forms, Lists, sharing, drag/drop, and
  system settings are reused instead of reimplemented.
- The app consistently uses SF Symbols and system typography.
- Battery telemetry has strong visual hierarchy and explicit combined accessibility elements.
- Decorative sparklines, timer rings, and playback bars are hidden from accessibility where a text
  equivalent exists.
- Live system and battery sampling is scoped to view visibility; paused media and inactive timers
  avoid unnecessary timeline work.
- Empty content, permission denial, advertisement-disabled controls, and unavailable telemetry are
  already considered in many surfaces.
- The new marquee preserves full announcements and respects Reduce Motion.
- The menu-bar icon now adapts automatically to native light/dark/selected menu-bar states.

## Recommended actions

1. **[P1] `/impeccable harden`:** complete action labels, state semantics, keyboard focus, and a
   non-hover shelf removal path.
2. **[P1] `/impeccable animate`:** apply Reduce Motion to playback bars, HUD interpolation, and timer
   progress behavior.
3. **[P1] `/impeccable adapt`:** make internal island rows survive long/localized text and make
   Settings resizable without changing the product’s fixed outer island.
4. **[P2] `/impeccable onboard`:** separate loading/empty/denied/failed states and add permission
   recovery actions.
5. **[P2] `/impeccable optimize`:** measure and then remove image decoding, app metadata lookup, and
   heavy calendar mapping from frequent main-thread render paths.
6. **[P2] `/impeccable document`:** capture the incumbent dark-island visual roles and activity
   accent rules before token extraction.
7. **[P3] `/impeccable polish`:** run a final keyboard, VoiceOver, contrast, localization, and
   multi-notch-size pass after the structural work.

You can run these one at a time, all at once, or in any order. Re-run the UI audit after fixes to
measure the score again.
